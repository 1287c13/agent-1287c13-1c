# AGENTS.md - указатель 1C-агента

Этот файл уходит в каждый запрос, поэтому он содержит только указатель: где что лежит.
Точка входа для пользователя - `START.md`; развёрнутые правила - `.clinerules\`.

## Правила: шесть коротких операционных файлов

| Файл | О чём |
|------|-------|
| `.clinerules\00-contract.md` | формат задачи, порядок работы, преамбула и отчёт, запреты |
| `.clinerules\10-mcp-and-skills.md` | какой вопрос каким слоем решается, состав MCP-инструментов и скиллов |
| `.clinerules\20-1c-platform.md` | базы 1С, платформы на машине, кириллица, стиль BSL |
| `.clinerules\30-verification.md` | чем подтверждается результат по каждому слою |
| `.clinerules\40-lessons.md` | инварианты, добытые дорого: грабли MCP, Vanessa, PowerShell 5.1 |
| `.clinerules\50-harness.md` | задачи по самому харнессу: что можно менять, чем проверять, git |

## Формат задачи

```
как <роль> сделай <действие> в базе <база> чтобы <цель> по START.md
как инженер харнесса сделай <действие> чтобы <цель> по START.md
```

`<база>` разрешается по `.v8-project.json` (id, alias, name или путь). Задача не в этом
формате не выполняется - попросить переформулировать.

Короткая команда **"измени переменную"** слотов не требует: `CLINE_MCP_SETTINGS_PATH`
наводится на текущий каталог скриптом `scripts\set-cline-mcp-path.ps1`
(`.clinerules\00-contract.md`, п.1.3). Пробы живости и подъем слоёв - под задачу,
а не «на всякий случай».

## Обязательный ответ

Первый блок - преамбула (`Слой:`, `MCP:`, `Скиллы:`, `Проверка:`), последний - отчёт
(`Сделано:`, `Проверка:`, `Не проверено:`). Дословный формат - `.clinerules\00-contract.md`.

## Запреты (полностью - в `.clinerules\00-contract.md`)

- Не выдумывать: имена объектов, реквизитов, методов и MCP-инструментов подтверждаются
  живой базой, индексом кода, справкой платформы или файлом проекта.
- Не писать свой скрипт, если для операции есть MCP-инструмент или скилл.
- Не заявлять об успехе без проверки: «должно работать» - не результат.
- Артефакт-первым: подъём слоёв и попутные починки - только если это в цели задачи.
- Не трогать файлы вне каталога проекта; базы 1С - только по явной задаче.
- Разбор кейса - файлом в `analysis\`, а не в переписке и не в доки.
- Коммит - только у инженера харнесса; в задачах по базе 1С git не трогается никогда.
- Не раздувать префикс: бюджет всегда-инжектируемого текста проверяет
  `scripts\check-context.ps1`.

## Слои

| Вопрос | Слой |
|--------|------|
| что в базе лежит сейчас, изменить и подтвердить | MCP `1c-toolkit` |
| из чего состоит объект, кто что вызывает | MCP `1c-code-index` |
| существует ли метод платформы, его сигнатура | MCP `1c-platform-help` |
| как собрать, разобрать или проверить артефакт | скиллы `.cline\skills` |
| путь и платформа базы | `.v8-project.json` |

Ответы, комментарии в коде и документация - по-русски; идентификаторы метаданных -
как в конфигурации.
