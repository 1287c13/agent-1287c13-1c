# AGENTS.md — контракт 1C-агента

Этот репозиторий — харнесс 1C-агента для Cline. Файл действует всегда.
Точка входа для пользователя: **`START.md`**. Развёрнутая версия правил:
`.clinerules/00-contract.md`, `.clinerules/10-mcp-and-skills.md`,
`.clinerules/20-1c-platform.md`, `.clinerules/30-verification.md`,
`.clinerules/40-lessons.md` (грабли и уроки — дописывается по ходу работы),
`.clinerules/50-harness.md` (задачи по самому харнессу, без базы).

## Формат задачи

```
как <роль> сделай <действие> в базе <база> чтобы <цель> по START.md
```

- `<база>` разрешается по `.v8-project.json` (путь, `id`, `alias`, `name`).
- Задача не в этом формате не выполняется — попросить переформулировать.

## Обязательная преамбула (первый блок ответа)

```
Слой: <какой слой решения задействован>
MCP: <какие MCP-инструменты будут вызваны>
Скиллы: <какие скиллы будут прочитаны>
Проверка: <чем подтвердится результат>
```

## Обязательный отчёт (последний блок ответа)

```
Сделано: ...
Проверка: ...
Не проверено: ...
```

## Жёсткие запреты

- **Не выдумывать** имена объектов, реквизитов, форм, полей, таблиц и методов
  платформы. Подтверждать через MCP-инструмент, скилл или файл проекта.
- **Не выдумывать MCP-инструменты.** Только реально подключённые серверы:
  `1c-toolkit` (живая база), `1c-code-index` (поиск по выгрузке),
  `1c-platform-help` (справка API платформы). Полный список - в
  `.clinerules/10-mcp-and-skills.md`.
- **Не писать свои скрипты вместо готового инструмента.** Есть MCP-инструмент или
  скилл - используется он.
- **Не трогать файлы вне каталога проекта.** Базы 1С - только по явной задаче.
- **Не заявлять об успехе без проверки.** «Должно работать» - не результат.
- **Артефакт-первым.** Задача просит артефакт (сценарий, XML, описание) - сдаётся
  артефакт. Подъём публикаций, настройка базы, вспомогательные скрипты «по пути» -
  только если это прямо входит в `<цель>`.
- **Не расширять периметр задачи.** Проблему, найденную попутно, не решают внутри
  задачи: она фиксируется в правилах или в `docs/06-troubleshooting.md` и
  закрывается отдельно. Дыра в харнессе закрывается **до** задачи - инструментом
  в `scripts` или скилле, а не заплаткой в её ходе.
- **Урок дописывается сразу.** Факт, добытый дорого (защита записи toolkit,
  отсутствие Vanessa в базе, OData-404), уходит в `.clinerules/40-lessons.md`
  в том же ответе, где обнаружен.
- **Результат анализа - в `analysis\`, а не в доки и не в `temp\`.** Разбор кейса
  сохраняется файлом `analysis\<ГГГГ-ММ-ДД>_<ЧЧММ>_<краткое-имя>.md`
  (`scripts\new-analysis.ps1`), путь называется в отчёте. Каталог в `.gitignore`.
- **Коммитит только инженер харнесса.** В задачах по базе 1С git не трогается никогда.
  Задача по харнессу не закончена, пока правки не отправлены в `origin`
  (`.clinerules/50-harness.md`, п.3).

## Разделение слоёв

| Вопрос | Слой |
|--------|------|
| что лежит в базе сейчас, изменить и подтвердить | MCP `1c-toolkit` |
| из чего состоит объект в конфигурации, кто что вызывает | MCP `1c-code-index` |
| существует ли метод платформы, его сигнатура | MCP `1c-platform-help` |
| как собрать, разобрать или проверить артефакт | скиллы `.cline/skills` |
| путь и платформа базы | `.v8-project.json` |

Факт о конкретной базе, взятый не из живого MCP-инструмента, считается выдуманным.

## Язык

Ответы, комментарии в коде и документация - по-русски. Идентификаторы метаданных -
как в конфигурации.
