# Специфика 1С в этом окружении

## Разрешение базы

Любое упоминание базы (`в базе <база>`) разрешается по `.v8-project.json` в корне проекта:

1. Точный путь (`File="..."` или `C:\...`) - использовать как есть.
2. `id` / `alias` / `name` / `aliases[]` - найти запись в `databases[]`.
3. Неоднозначность или отсутствие записи - спросить пользователя, не угадывать.

Поля записи: `id`, `name`, `type` (`file`|`server`), `path` (для `file`),
`server`/`ref` (для `server`), `user`, `password`, `v8path` (платформа именно
этой базы), `aliases`, `webUrl`, `configSrc`.

Скиллы группы `db-*` и `1c-db-*` читают этот файл сами - не дублировать их логику.

## Платформы на этой машине

| Версия | Каталог bin | Справка `shcntx_ru.hbk` |
|--------|-------------|-------------------------|
| 8.3.27.2130 | `C:\Program Files\1cv8\8.3.27.2130\bin` | есть |
| 8.3.25.1374 | `C:\Program Files\1cv8\8.3.25.1374\bin` | нет |
| 8.3.24.1819 | `C:\Program Files\1cv8\8.3.24.1819\bin` | есть |

По умолчанию - 8.3.27.2130 (`v8path` в `.v8-project.json`).

Чего на машине **нет** и что из этого следует:

- **нет 1С 7.7** - задачи по 77 не выполнять, сообщать об отсутствии платформы;
- **нет Docker** - docker-based инструменты (в т.ч. `1C_SyntaxChecker`, Docker-сборка
  proxy 1C MCP Toolkit) недоступны; вместо них офлайн-валидаторы скиллов;
- **нет Node.js / npx** - `mcp-remote` и npm-обёртки недоступны;
- **нет Java** - инструменты на JVM недоступны;
- Python: `py -3` (3.14), `py -3.9`, `py -3.8`. Для venv сервера справки
  используется `py -3`.

## Запуск платформы

Пакетный запуск: `1cv8.exe <CREATEINFOBASE|DESIGNER|ENTERPRISE> ...`. Готовые
обёртки - в скиллах `db-*`: `db-run`, `db-create`, `db-load-xml`, `db-update`,
`db-dump-cf`, `db-dump-dt`, `db-load-git`, `db-repo`, `db-list`.

Приложение в браузере / публикация - `web-publish`, `web-info`, `web-stop`,
`web-test` (скиллы cc-1c). Требуют Apache; путь задаётся в `.v8-project.json`
(`webPath`).

## Кириллица, кодировки, кавычки

Полный набор правил - `skills-vendor\cursor-1c-skills\rules\1c-cyrillic-windows.mdc`
(читать, когда в путях, именах баз, пользователей или аргументах есть кириллица,
либо когда запускается платформа). Кратко:

- пути и аргументы с кириллицей передавать так, чтобы не терялись кодировкой;
- `.ps1`-файлы с русским текстом сохранять в UTF-8 **с BOM** (иначе Windows
  PowerShell 5.1 читает их как ANSI и ломает строки);
- в генерируемом тексте не использовать длинное тире, букву «ё» и кавычки-ёлочки
  (`skills-vendor\cursor-1c-skills\rules\text-formatting.mdc`).

## Стиль кода

Перед написанием BSL читать `skills-vendor\cursor-1c-skills\rules\1c-coding-standards.mdc`.
Ключевое: шапка-описание обязательна у каждой процедуры и функции; запросы в цикле
запрещены; режим - стандарты 1С (ИТС), подтверждать через `get_coding_guideline`.

## Ограничения, которые нужно называть вслух

- Индекс кода и валидаторы работают **по выгрузке**, а не по живой базе. Если
  выгрузка не соответствует базе - выводы могут не соответствовать.
- Статическая проверка подтверждает имена и структуру, но **не** типы выражений,
  семантику BSL и план запроса. Это доступно только на платформе.
- Встроенный сервер 1C MCP Toolkit поднимается скриптом `scripts\start-toolkit.ps1` на одну базу за раз (порт 6003); сеанс гасится `scripts\stop-toolkit.ps1` - он занимает клиентскую лицензию базы.
  Работа с другой базой требует переключения сервера.
