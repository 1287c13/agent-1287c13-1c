# MCP и скиллы: что чем решается

Правило: **сначала инструмент, потом собственный код**. Ниже - карта доступных
инструментов. Использовать только реально подключённые MCP-серверы; вызов
несуществующего инструмента - ошибка.

## Слои решения (выбор по типу вопроса)

| Вопрос | Слой | Средство |
|--------|------|----------|
| Что сейчас лежит в базе: данные, документы, справочники | живая база | MCP `1c-toolkit` |
| Выполнить код/запрос прямо в базе | живая база | MCP `1c-toolkit` |
| Опубликованные метаданные, OData, HTTP-сервисы базы | живая база | MCP `1c-toolkit` |
| Состав метаданных, реквизиты, формы, модули по выгрузке | индекс кода | MCP `1c-code-index` |
| Найти процедуру, кто её вызывает, структуру объекта | индекс кода | MCP `1c-code-index` |
| Есть ли у платформы такой метод, сигнатура, тип | справка платформы | MCP `1c-platform-help` |
| Как писать BSL по стандартам, строгая типизация | справка платформы | MCP `1c-platform-help` |
| Формат объекта метаданных, сборка/разбор XML, валидация | скиллы | `.cline\skills\*` |
| Gherkin/Vanessa, сценарии автотестов | скиллы | `.cline\skills\va-*`, `vanessa-*` |
| Задача пришла из внешней очереди (очередь на сервере, доставка URI) | файлы проекта + живая база | файл ответа `temp\queue\<id>\answer.md`, затем `py -3 integration\agent.py --write-result`; `docs\07-external-integration.md` |
| Прогнать Gherkin-сценарий в базе (только если этого требует задача) | скрипты харнесса + живая база | `scripts\vanessa-run.ps1` (Vanessa - внешняя обработка платформы, в конфигурацию не ставится; обработку разворачивает сам, сеанс toolkit освобождает ключом `-FreeToolkit`); предпосылки - `.clinerules\40-lessons.md`, п.12 |
| Нужен инструмент, а слой не поднят | живая база / индекс кода | агент поднимает сам: `scripts\start-toolkit.ps1` (база), `scripts\start-harness.ps1 -Layer Index` (индекс); пробы живости - только под задачу или по просьбе (`check-harness.ps1 -Health`) |
| Свойства конкретной информационной базы (путь, платформа) | файлы проекта | `.v8-project.json` |
| Список репозиториев индекса и их состояние | файлы проекта + скрипты харнесса | `.cline\mcp\code-index-mcp\home\daemon.toml` (алиасы) и `scripts\check-harness.ps1` (статусы из `/health` демона); не вызовом `get_stats` |

## MCP-серверы харнесса

### 1. `1c-toolkit` - живая база (главный слой)

Встроенный HTTP-сервер обработки `MCP_Toolkit.epf`, транспорт `streamableHttp`,
адрес `http://127.0.0.1:6003/mcp`. Поднимается скриптом `scripts\start-toolkit.ps1`
(база - из `.v8-project.json`, автозапуск обработки ключом
`/C "startup;mode=embedded;port=6003"`), гасится `scripts\stop-toolkit.ps1`. Ручной
путь тоже рабочий: открыть `.cline\mcp\1c-mcp-toolkit\MCP_Toolkit.epf` в нужной базе
и включить режим «Встроенный сервер».

Основные инструменты: `execute_query` (запрос по базе), `execute_code` (код на
BSL внутри базы), `get_metadata` (состав и структура метаданных), `get_event_log`,
`get_access_rights`, `get_object_by_link`, `get_link_of_object`,
`find_references_to_object`, `get_bsl_syntax_help`, `restart_1c_session`.
Полный перечень и точные имена - у самого сервера.
Часть редких инструментов всех трёх серверов отключена в настройках (`disabledTools`),
чтобы их схемы не уходили в каждый запрос: перечень отключённого, причина и способ вернуть -
`docs\04-mcp-servers.md`. Здесь названы инструменты, которые должны быть видны модели
всегда.

Это единственный слой, дающий факты о **текущем состоянии** конкретной базы.
Без него задача, требующая данных, не выполняется - вместо ответа сообщается,
что сервер не поднят.

### 2. `1c-code-index` - структурный поиск по выгрузке

`bsl-indexer.exe serve`, транспорт stdio, запускается Cline сам. Требует
запущенного фонового индексатора (`scripts\start-harness.ps1`).

Инструменты: `get_object_structure`, `get_object_profile`, `get_form_handlers`,
`get_event_subscriptions`, `get_register_writers`, `find_references`,
`find_data_path`, `get_role_rights`, `find_path_bsl`, `search_terms`, `bsl_sql`,
а также общие `read_file`, `list_files`, `grep_code`, `grep_body`, `search_text`,
`get_stats`, `health`. У репозитория алиас `main`.

Это слой **статического анализа**: платформа не запускается, данные не читаются.

Быстрые факты об индексе - вместо дорогих вызовов. `get_stats` - самый дорогой инструмент
сервера (9,0 с по корню проекта, 6,6 с по выгрузке КА против 0,05 с у `daemon status`),
поэтому список репозиториев берут из `daemon.toml`, состояние - из `/health` демона
(и то лишь с ключом `-Health`), а `get_stats` - только по конкретному `repo`.

### 3. `1c-platform-help` - справка API платформы

`mcp-bsl-context.exe` (venv внутри проекта), транспорт stdio. Источник -
`shcntx_ru.hbk` установленной платформы 1С.

Инструменты: `search`, `info`, `get_member`, `get_members`, `get_constructors`,
`get_platform_info`, `get_coding_guideline`, `get_strict_typing_info`,
`search_strict_typing`.

Используется, когда нужно подтвердить существование метода, его сигнатуру, типы
параметров и возвращаемое значение. Проверять сигнатуру по этому серверу
**до** написания строки кода.

## Скиллы

Скиллы лежат в `.cline\skills\`. Их 206; они собраны из шести вендорских наборов
(см. `SOURCES.md`). Cline подгружает метаданные скиллов и
читает `SKILL.md` целиком только когда скилл релевантен задаче.

Практическое правило: **сначала роутер, потом профильный скилл**.

| Задача | Скилл-точка входа |
|--------|-------------------|
| Не знаю, каким скиллом решать | `1c-config-router` |
| Собрать/разобрать объект метаданных | `meta-compile` / `meta-decompile`, `1c-meta-compile` |
| Формы | `form-compile` / `form-edit`, `1c-form-compile` |
| База: создать, выгрузить, загрузить, обновить, запустить | `db-*`, `1c-db-*` |
| Роли, СКД, макеты, XDTO, подсистемы | `role-*`, `skd-*`, `mxl-*`, `xdto-*`, `subsystem-*` |
| Расширения и внешние обработки | `cfe-*`, `epf-*`, `erf-*`, `1c-cfe-*` |
| Веб-публикация и тесты в браузере | `web-publish`, `web-test`, `web-info` |
| Gherkin и Vanessa Automation (авторство сценария) | `va-scenario-generator`, `Vanessa_for_AI`, `1c-vanessa-steps`; прогон - не скилл, а `scripts\vanessa-run.ps1` |
| Валидация результата без платформы | `1c-bsl-validate`, `1c-code-review`, `*-validate` |
| Стандарты BSL и строгая типизация | правило `skills-vendor\cursor-1c-skills\rules\1c-coding-standards.mdc` |

Правила вендора (`skills-vendor\cursor-1c-skills\rules\*.mdc`, 40 файлов)
специально **не** подключены как постоянные правила: Cline не знает про
`globs`/`alwaysApply` и включил бы их все разом. Они читаются по надобности как
справочник - по одному файлу под задачу.

## Что запрещено

- Вызывать MCP-инструмент, которого нет в этом списке и который сервер не отдаёт.
- Подменять слой: брать данные из индекса кода там, где нужны данные живой базы.
- Писать собственный скрипт, если для операции есть скилл или MCP-инструмент.
- Вызывать `get_stats` без нужды и без `repo`. Это не проверка живости: живость -
  `scripts\check-harness.ps1`; объём индекса нужен редко и всегда по конкретному `repo`.
