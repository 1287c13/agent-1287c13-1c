# Грабли и уроки харнесса

Файл действует всегда, то есть уходит в каждый запрос к модели, поэтому здесь только
**инварианты**: то, что дорого открывать заново. Разбор кейса (почему так вышло, цепочки
процедур, номера строк) сюда не пишется: он идёт файлом в `analysis\`, а здесь остаётся
строка-указатель (раздел 10). Бюджет проверяет `scripts\check-context.ps1`.

Правило: если факт стоил времени, в тот же ход он попадает сюда или в `analysis\`: знание,
оставшееся в переписке, теряется со следующей сессией. Если факт означает **отсутствие
инструмента**, сначала заводится инструмент (скрипт в `scripts\`, скилл, правило), и только
потом продолжается задача: заплатка внутри задачи - та же дыра, только замаскированная.

## 1. Артефакт-первым

Задача просит артефакт (сценарий, XML, описание, отчёт) - результат это **артефакт**.
Поднять живой слой, развернуть публикацию, настроить OData, пройти прогон, написать
вспомогательный скрипт - только если это входит в `<цель>`. Признак подмены приоритета:
прошло больше двух шагов, а артефакта всё ещё нет.

## 3. Живой слой: `1c-toolkit`

- **Защита записи.** `execute_code` отвечает `Операция запрещена: код содержит опасные
  ключевые слова: <слово>` при любом `Записать`. Фильтр стоит в самой обработке
  `MCP_Toolkit.epf`; параметр автозапуска `auto_allow_write` его не снимает (проверено).
  Штатный путь один - снять флаг в форме обработки. Об этом сообщается строкой
  «Не проверено: запись невозможна, защита не снята», а не обходится формулировками BSL.
- **Инструментов в сеансе может не быть.** Сервер подключён по `streamableHttp`: если он
  поднят после старта VS Code, Cline инструменты не регистрирует. Перезапуск VS Code не
  обязателен - у обработки есть документированный REST API
  (`POST http://127.0.0.1:6003/api/<имя инструмента>`: `execute_code`, `execute_query`,
  `get_metadata`, `get_object_by_link`). Тело собирать `ConvertTo-Json` и отдавать как
  UTF-8, ответ читать тоже как UTF-8 (`RawContentStream`), иначе кириллица битая.
- **Тяжёлая база поднимает toolkit минутами.** `demo-ar` (КА, 4,3 ГБ, свободной памяти
  меньше 1 ГБ) дала `/health` через ~3,5 мин, `demo-ssl` - через 9-12 с. Ключ `-NoWait`
  возвращает управление сразу, поэтому health опрашивают циклом, а не считают сервер
  не поднявшимся. Клиент занимает клиентскую лицензию базы: `scripts\start-toolkit.ps1`
  идемпотентен, повторный запуск - только ключом `-Force`.
- **Закрытие сеанса.** `POST /api/close_1c_session` с телом `{}` возвращает 200 и освобождает
  порт: обработка закрывает сеанс сама. Резерв - `scripts\stop-toolkit.ps1` (гасит процесс
  1С с `MCP_Toolkit.epf` в командной строке). Скрипт обязан гасить и «зависший» сеанс:
  сервер молчит, а порт и клиентскую лицензию сеанс занимает.
- **`get_stats` дорогой.** Замер: `stats` по корню проекта - 9,0 с, по выгрузке КА - 6,6 с,
  а `daemon status` (`GET /health` демона) - 0,05 с. Живость слоя проверяется дешёвым
  средством (`scripts\check-harness.ps1`), а `get_stats` берётся только по конкретному `repo`.
- **Мелкие ловушки платформы, стоившие ходов.** `Метаданные` - свойство, а не метод
  (`Метаданные.Справочники.Количество()`); у объекта `Файл` `ЭтоКаталог` - метод
  (`Ф.ЭтоКаталог()`); у `КоллекцияКолонокТаблицыЗначений` нет `ВыгрузитьКолонку` (он у самой
  `ТаблицаЗначений`); обход `Для Каждого Знч Из Перечисления.X` даёт ссылку без `.Имя` -
  имена брать из `Метаданные.Перечисления.X.ЗначенияПеречисления`.
- **Формат `execute_code` через REST.** Текст запроса внутри `Запрос.Текст = "..."` должен
  быть **одной строкой** (многострочный литерал с `|` даёт `Неопознанный оператор`);
  значение возвращает сама переменная `Результат` (строка `Результат;` в конце - та же
  ошибка компиляции); строковые литералы BSL - только в двойных кавычках (одиночные - это
  литерал даты).
- **Печатные формы проверяются серверно.** Для УПД - экспортная
  `Обработки.ПечатьОбщихФорм.СформироватьПечатнуюФормуУПД(...)`, `ОбъектыПечати` -
  **`СписокЗначений`**; разбор - раздел 10.
- **Реквизит документа в форму ЭДО не попадает:** форма показывает XML сообщения (разбор -
  раздел 10).
- **Очередь интеграции - на сервере**, у агента только `temp\queue\<id>\` на время задачи.
  Живой watcher - по замку `temp\queue\.watcher.lock`; claim - переименование файла.
- **Порядок очереди - по `created_ts`, не по имени:** хвост id случаен, строковая сортировка
  переставляет задачи одной секунды (`analysis\2026-10-19_1124_ochered-server-watcher.md`).
- **Passenger: вход `integration\passenger_wsgi.py`**, базовый URI - из `SCRIPT_NAME`.
## 4. OData: публикация не равна опубликованным метаданным

Корень публикации отвечает 200, а состав объектов (`/odata/standard.odata/$metadata`) - 404.
Причина: в конфигурациях на БСП стандартный интерфейс OData включается настройкой **в базе**
(`Обработка.НастройкаСтандартногоИнтерфейсаOData` заполняет
`Константа.ПользовательСтандартногоИнтерфейсаOData`). Пустая константа - пустой состав
публикуемых объектов. Разворот публикации закрыт готовым инструментом
`scripts\publish-odata.ps1`, повторно его писать не нужно. Настройка самого интерфейса -
отдельная задача **записи** в базу, то есть упирается в раздел 3.

## 5. Vanessa Automation

- Vanessa в конфигурацию базы **не ставится**: это внешняя обработка (`/Execute`), поэтому
  «в базе нет объектов Vanessa» - не причина отказаться от прогона. Релизный архив
  `vanessa-automation-single.<версия>.zip` разворачивается в один `epf`, библиотека шагов
  внутри. Инструменты харнесса: `scripts\install-vanessa.ps1` (разворачивает обработку) и
  `scripts\vanessa-run.ps1` (прогон; артефакты - в `.vanessa\`).
- Рабочая строка запуска: `1cv8c.exe ENTERPRISE /F"<база>" /N"<польз>" /P"<пароль>"
  /Execute "<...>\vanessa-automation-single.epf" /C"StartFeaturePlayer;VAParams=<...>\VAParams.json"
  /TESTMANAGER`. Ключ `VAParams` (устаревшие `VBParams`, `КлиентыТестирования` тоже работают),
  регистр значения `/C` не важен.
- **Лицензия - главная грабля.** Vanessa поднимает два клиентских сеанса (менеджер
  тестирования и клиент тестирования), и второй клиент той же базы платформа отвергает:
  «Превышено ограничение лицензии для разработчиков на количество клиентов информационной
  базы». Значит, перед прогоном базу освобождают от **всех** клиентских сеансов, включая
  сервер toolkit (порт 6003); `scripts\vanessa-run.ps1` делает это ключом `-FreeToolkit`.
  Отказ по лицензии и «Пользователь ИБ не идентифицирован» - разные отказы: второй означает
  отсутствие `user`/`password` в записи базы в `.v8-project.json`.
- Результаты прогона: `.vanessa\status.txt` (0 или 1), `va-log.txt` и `junit\junit.xml`
  (`Steps.xml` из статей не создаётся). Диагностика по порядку: `status.txt`, `va-log.txt`
  (ошибка шага и код), затем `junit.xml`.
- Шаги берутся только из реестра скилла `1c-vanessa-steps` (поиск и валидация скриптами);
  сочинять шаг запрещено. Шагов HTTP/OData в реестре нет: их выражает шаг «выполняю код
  встроенного языка на сервере» с блоком `"""bsl`.
  Формат `.feature`: UTF-8 без BOM, CRLF, табы, первая строка `# encoding: utf-8`.
  Сценарий под задачу - в `temp\features\` (дефолт `vanessa-run.ps1`), каталог `features\`
  в корне запрещён.
## 6. Индекс кода (`1c-code-index`)

- **`serve` и демон - разные процессы.** Инструменты данных (`bsl_sql`, `grep_*`, `search_*`)
  спрашивают демон по `http://127.0.0.1:8015`; без демона ответ `daemon_offline`, а по пути
  выгрузки - `not_started`. `get_stats` и `health` при этом отвечают (читают базу индекса
  напрямую), поэтому «индекс работает» по ним не проверяется. Первый шаг при молчащем
  индексе - `daemon status`, а не обход; поднимает `scripts\start-harness.ps1`. После старта
  демон сверяет время и размер файлов, и это минуты.
- **Выгрузка внутри корня проекта индексируется дважды** (отдельной секцией `[[paths]]` и как
  часть всего корня). После её появления слой надстройки уходит в перестройку: `bsl_sql`
  отвечает `status = "indexing"`, ядро (`grep_code`, `get_function`) при этом работает.
  Это не поломка.
- `language = "bsl"` в секции `[[paths]]` обязателен, иначе BSL-инструменты не регистрируются;
  после правки `daemon.toml` нужен reconnect MCP-сервера: список инструментов клиент сам
  не обновляет.
- **Исключать каталог надо до входа в него.** `Get-ChildItem -Recurse` с фильтром в теле
  цикла - полный обход дерева (в харнессе это стоило полутораминутного чекера вместо 4,4 с);
  обход вести своим стеком по `EnumerateDirectories/EnumerateFiles`, пропуская каталог целиком.
  Дефолт скрипта - не корень проекта: рекурсия по `dump\` даёт таймаут (`fix-encoding.ps1`).
- Индексировать каталог можно только после конца выгрузки: пока она идёт, дерево
  дописывается, и индекс получается по половине конфигурации.
- **Числа живой базы и выгрузки не сходятся, и это не пропуск файлов.** `DumpConfigToFiles`
  без ключей выгружает только основную конфигурацию: объектов расширения (например, модули
  `ИТК*` в КА2) в выгрузке нет. Расхождение берут по именам объектов, а не вычитанием одного
  числа из другого.
- **`Документ.X`, а не `Документы.X`.**

## 7. PowerShell 5.1 (эта машина)

- `Get-Content` без `-Encoding UTF8` читает UTF-8 как ANSI: путь из `.v8-project.json`
  превращается в кракозябры, и база «не находится». Читать так:
  `Get-Content .v8-project.json -Raw -Encoding UTF8 | ConvertFrom-Json`.
- `.ps1` с кириллицей сохранять в UTF-8 **с BOM** (`scripts\fix-encoding.ps1`), иначе 5.1
  разбирает файл как ANSI и валится каскадом `Missing closing ')'`. После правки `.ps1`
  сначала идёт `fix-encoding`, а проверка - **отдельной** командой: команды одной пачки
  выполняются параллельно, и холостой прогон успевает прочитать файл до записи BOM.
- Нет тернарного оператора `? :` (это PS 7); у скаляра нет `.Count` - оборачивать `@(...)`;
  `"$repoName:"` разбирается как имя диска - писать `${repoName}:`; `$home` - постоянная
  переменная, для локальной брать другое имя.
- `-EncodedCommand` на машине блокируется антивирусом («Этот сценарий содержит вредоносное
  содержимое»): разовый сценарий оформлять файлом в `temp\` и запускать `-File`.
- Нативные команды (CLI индексатора, `git`) пишут прогресс в stderr, а 5.1 превращает это
  в `NativeCommandError`. В замерах добавлять `2>$null`; код возврата `git push` не
  показатель - отправку проверять по `git ls-remote origin refs/heads/main` против
  `git rev-parse HEAD`.
- **Лимит одной команды агента - 30 с.** Тяжёлые операции (`git add` десятков тысяч файлов,
  robocopy больших каталогов) дробить по частям. Убитый по таймауту `git add` оставляет
  `.git\index.lock`: если процессов `git` нет - удалить lock и повторить.
- **Битый JS виден только браузеру:** `SyntaxError` в `integration\web\app.js` даёт пустую
  страницу при живом сервере; проверять консоль (F12) и `scripts\check-harness.ps1`.

## 8. Платформа, API и данные

- **Навигационную ссылку не собирать руками.** `ref` - не UUID без дефисов: порядок байт
  другой, и склеенная вручную ссылка даёт «Объект не найден или недостаточно прав доступа».
  Ссылку брать готовой из `get_link_of_object`.
- **Метод-заглушка вместо пустоты.** `ЭлектронноеВзаимодействиеУТ.ПолучитьДанныеЮрФизЛица(ПустаяСсылка, ...)`
  возвращает структуру-заготовку (37 ключей, заполнено 0), поэтому `ЗначениеЗаполнено(...)` даёт
  Истина и пустой участник проходит в XML: такие условия проверять живьём, а не глазами.
- **Неэкспортные методы конфигурации из `execute_code` не видны** («Метод объекта не
  обнаружен»). Выводы по ним делает только индекс кода.
- **Очень крупные модули (мегабайты, ЭДО) поиском по тексту не берутся.** Сначала запрос
  к таблице функций индекса (`bsl_sql`), затем чтение диапазона строк (`read_file`).
- **Вендорские каталоги в git не коммитятся.** `skills-vendor\` разворачивается
  `scripts\install-vendor-repos.ps1`, скиллы собираются `scripts\install-vendor-skills.ps1`.
  Признак ошибки: `git add` вендоров не укладывается в 30 с и оставляет `.git\index.lock`.
- Кириллица в путях и аргументах запуска платформы - правила
  `skills-vendor\cursor-1c-skills\rules\1c-cyrillic-windows.mdc`; в генерируемом тексте
  не использовать длинное тире, букву «ё» и кавычки-ёлочки (`text-formatting.mdc`).
- Числа в доках считаются по факту и по карте источников (`install-vendor-skills.ps1`),
  а не обходом каталогов: у вендоров каталоги скиллов дублированы.

- **Загрузчик 60989 (ФТО, остатки товаров):** партия создается по ГРУППЕ строк, а `ВводОстатковТоваров` ищется БЕЗ партии и при найденном очищает ТЧ (стр. 226) - лишние партии теряются (разбор - `analysis\2026-10-15_1713_zapros-ostatki-tovarov-partii.md`).

## 9. Реестр знаний и бюджет префикса

Место артефакта задаётся его природой, а не удобством:

| Что | Куда |
|-----|------|
| правило, инструкция, чек-лист (должно жить в репозитории) | `.clinerules\`, `docs\` |
| разбор кейса, расследование, «почему так» | `analysis\` (`scripts\new-analysis.ps1`) |
| разовый скрипт, выгрузка ответа, лог, черновик | `temp\` |
| инвариант, добытый дорого | `.clinerules\40-lessons.md` (одна строка) |
| накопленный объём дерева | `dump\`, `.code-index\`, `.vanessa\`, `logs\` (в `.gitignore`) |

- Ссылка на файл анализа дается **полным путём** (`analysis\2026-10-14_1211_upd-gruzopoluchatel-edo.md`):
  голое имя чекер не находит - каталог `analysis` исключён из обхода.
- **Бюджет префикса проверяет `scripts\check-context.ps1`:** `.clinerules` - не более
  45 000 символов, внутри него `40-lessons.md` - 15 500, `AGENTS.md` - 3 000, метаданные
  скиллов - 6 000. Файлы правил уходят в каждый запрос целиком, кириллица в токенизаторах
  плотнее латиницы, а окно модели ограничено (128 000, авто-сжатие истории).
- Признак, что бюджет пробит: растёт `tokensIn` первого запроса сессии, авто-сжатие
  срабатывает чаще, детали прежних ходов теряются. Лечится не сокращением работы, а
  переносом разбора в `analysis\`.
- Задача по харнессу заканчивается коммитом и отправкой в `origin`; задача по базе 1С
  git не трогает никогда.
