# Харнесс 1C-агента для Cline

Рабочее место, в котором пользователь ставит задачу в едином формате, а Cline
выполняет её как 1С-агент - на MCP-серверах и скиллах сторонних вендоров.

Всё решение (харнесс, скиллы, MCP-серверы) лежит **внутри каталога проекта**.
За пределами проекта - ровно одно действие: переменная окружения
`CLINE_MCP_SETTINGS_PATH`, без которой Cline не умеет читать in-project
конфигурацию MCP.

## 1. Требования к машине

| Что | Состояние |
|-----|-----------|
| ОС | Windows |
| VS Code + расширение Cline | `saoudrizwan.claude-dev` |

| Python-лаунчер | `py -3` (для MCP-сервера справки) |

## 2. Установка из репозитория

Репозиторий самодостаточен: в git лежат конфиг, скрипты и скиллы, бинарники
MCP-серверов восстанавливаются скриптом (они крупные и в git не хранятся).

Выполнять из корня проекта, по порядку:

```powershell
# 1. Вендорские репозитории (скиллы, правила, комплект 1C MCP Toolkit)
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-vendor-repos.ps1

# 2. Бинарники MCP-серверов внутрь .cline\mcp (индексатор кода, .epf, venv справки)
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-mcp.ps1

# 3. Сборка скиллов в .cline\skills
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-vendor-skills.ps1

# 4. Подключение MCP: daemon.toml, запуск индексатора, CLINE_MCP_SETTINGS_PATH
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-mcp.ps1
```

После шага 4:

5. **Полностью закрыть и заново открыть VS Code** - переменная окружения
   читается при старте.
6. Открыть в 1С файл `.cline\mcp\1c-mcp-toolkit\MCP_Toolkit.epf`, выбрать режим
   **«Встроенный сервер»** и нажать **«Запустить сервер»** (порт 6003). Это
   подключает слой живой базы.
7. Проверить: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-harness.ps1`

---

## 3. Ежедневный запуск

После перезагрузки машины поднять фон:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-harness.ps1
```

Скрипт поднимает индексатор кода и напоминает про сервер живой базы.
Чтобы не запускать вручную - положите ярлык на скрипт в автозагрузку
(`Win+R` -> `shell:startup`).

## 4. Как ставить задачу

Единственный формат:

```
как <роль> сделай <действие> в базе <база> чтобы <цель> по START.md
```

Примеры:

```
как программист 1С сделай обработку печати счёта в базе демо чтобы печаталось по кнопке по START.md
как тестировщик сделай Gherkin-тест проведения документа в базе File="C:\...\DemoARAutomation20" чтобы документ проводился с комментарием по START.md
как аналитик сделай описание структуры документа ПоступлениеТоваров в базе erp чтобы понять движения по регистрам по START.md
```

Агент отвечает преамбулой `Слой / MCP / Скиллы / Проверка`, выполняет задачу и
заканчивает блоком `Сделано / Проверка / Не проверено`.

## 5. Что где лежит

| Путь | Что это |
|------|---------|
| `START.md` | протокол работы агента (читается всегда) |
| `AGENTS.md` | краткая выжимка контракта |
| `.clinerules/` | постоянные правила Cline (контракт, MCP и скиллы, специфика 1С, проверка, грабли и уроки) |
| `.cline/skills/` | 206 скиллов из шести вендорских наборов (собираются из `skills-vendor/`) |
| `.cline/cline_mcp_settings.json` | конфигурация MCP-серверов (в git) |
| `.cline/mcp/` | бинарники MCP-серверов (не в git, ставятся скриптом) |
| `.v8-project.json` | базы и путь к платформе 1С |
| `scripts/` | установка, запуск, диагностика, публикация OData (`publish-odata.ps1`) |
| `skills-vendor/` | вендорские репозитории: в git не хранятся, разворачиваются `install-vendor-repos.ps1` |
| `SOURCES.md` | внешние источники и зафиксированные версии |
| `docs/` | описание решения; `docs/legacy/` - документация первой версии |
| `mcp/` | доки по MCP-серверам и пример конфигурации (в примере `<КОРЕНЬ>` заменяется на путь к харнессу) |

## 6. Диагностика

```powershell
# полная проверка харнесса
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-harness.ps1
```

Частые случаи - [docs/06-troubleshooting.md](docs/06-troubleshooting.md).

Типовые причины:

- **агент не видит MCP-серверы** - VS Code не перезапускали после `enable-mcp.ps1`;
- **`daemon_offline`** - не запущен индексатор, выполните `start-harness.ps1`;
- **нет инструментов живой базы** - не запущен встроенный сервер в `MCP_Toolkit.epf`;
- **сервер справки молчит** - в `v8path` нет файла `shcntx_ru.hbk` (в 8.3.25 его нет; используйте 8.3.27);
- **`execute_code` отвергает код** («код содержит опасные ключевые слова») - включена защита записи в `MCP_Toolkit.epf`, снимается флагом в форме обработки;
- **OData-публикация открывается, а `$metadata` даёт 404** - стандартный интерфейс OData в базе не настроен (пустая константа БСП), публикует `scripts\publish-odata.ps1`;
- **сценарий Vanessa написан, но не прогоняется** - в базе нет Vanessa Automation, установка - задача `vanessa-project-bootstrap`.

## 7. Что выходит за пределы проекта

Одно действие: пользовательская переменная окружения `CLINE_MCP_SETTINGS_PATH`.
Cline читает MCP только из глобального файла; эта переменная указывает на файл
**внутри проекта** (`.cline\cline_mcp_settings.json`). Обратного пути нет -
без переменной in-project MCP недостижим.

Дополнительно, по желанию: ярлык в автозагрузке на `start-harness.ps1`.
