# Сценарии Vanessa Automation: запись → доводка → прогон

Skill собран по итогам проверки концепции (PoC) в сентябре–октябре 2026: 1С:ERP (демо-база), платформа 8.5.1.1343, Vanessa Automation 1.2.043.42 с MCP-сервером, client_mcp 0.6.5, VAExtension 1.32. Источники правил: база знаний VA (вопросы Q1–Q102), исходники движка VA, официальная статистика употребления шагов VA, практика сценарного тестирования. Итоги проверки и сравнение подходов — в README репозитория и в ролике.

## Ключевые принципы

1. **Имена элементов формы не угадываются.** Источник имён — запись рекордера или интроспекция формы через MCP (`get_form_analysis`, `get_object_attributes`). Генерация по тестплану без этого на реальной форме падает на первых же полях.
2. **Сырая запись рекордера — не тест.** Она содержит недетерминированный выбор, жёсткие номера, лишние шаги, недопустимые для `check_syntax` заголовки и ни одной проверки. Доводка обязательна (раздел «Чек-лист доводки записи»).
3. **Готов только прогнанный сценарий.** Зелёный `check_syntax` + зелёный прогон + повторный прогон + проверка очистки по данным. Самоотчёт агента и визуальная правильность текста — не критерий: в PoC агент объявил 5/5 проверок при фактически нерабочей очистке и слабых проверках, а автор, знавший правило про `*`, сам нарушил его — поймал только `check_syntax`.
4. **БЗ VA задаёт правила, статистика — словарь.** Статистика показывает, что пишут на реальных проектах (включая плохие практики: `Пауза`, `закрываю текущее окно`), БЗ — как правильно. При конфликте — БЗ, с учётом известных дефектов самой БЗ (раздел «Правила»).

## Выбор режима

| Режим | Когда | Вход | Затраты (PoC) |
|---|---|---|---|
| **1. Запись + доводка** (основной) | есть человек, знающий процесс; есть доступ к клиенту 1С | сырая запись рекордера + тестплан | ≈ 2 мин человека + ≈ 15 мин агента, 17 вызовов MCP; зелёный с первого прогона |
| **2. Исследование через MCP** (запасной) | человека нет; новые формы; пакетная генерация по тестплану | тестплан + MCP VA | ≈ 40 мин агента, 85+ вызовов; требует обязательного ревью |
| **3. Черновик без MCP** (деградация) | нет ни записи, ни MCP | тестплан | быстро, но нерабочий без доводки на форме; выдавать только со списком допущений |

Если пользователь не указал режим: есть запись → режим 1; есть MCP и нет записи → предложить записать процесс (памятка ниже), иначе режим 2; нет ничего → режим 3.

## Формат входа: тестплан

Тест описывается блоками **Дано / Когда / Тогда** (`## Тест NN: Название`).

- «Дано» — предусловия: объекты, которые уже должны быть в базе; сценарий их не создаёт.
- «Когда» — действия, в том числе явное заполнение полей. Если тестплан говорит «организация X», поле заполняется явно, а не проверяется как значение по умолчанию: умолчания зависят от пользователя и базы.
- «Тогда» — каждому пункту в сценарии соответствует проверяющий шаг со значением; неавтоматизируемое оформляется `// ВЫНОС <n>: <причина>`.

Если тестплан пользователя в другом формате (ФТТ, ПМИ), сначала привести его к Дано/Когда/Тогда и согласовать.

Источник тестплана, если его нет: видеозапись процесса (скринкаст ключевого пользователя или консультанта, один сценарий на ролик). Нейросеть разбирает видео и пишет шаги и критерии проверки. Это дополнение к режиму 1, а не замена: видео даёт шаги и «Тогда», запись рекордера — точные имена элементов. Результат разбора видео — черновик: сверить с человеком, убрать сценарии, которыми пользователи не пользуются.

## Режим 1. Запись + доводка

### Памятка для записи (выдать пользователю)

1. VA открыт, клиент тестирования подключён, в клиенте закрыты все окна.
2. Запустить запись действий, выполнить ровно «Когда» тестплана по порядку, открывая всё через командный интерфейс.
3. **Ссылочные поля — только вводом текста в поле** и выбором из выпадающего списка. Не нажимать кнопку выбора, не открывать формы подбора, не брать «первую/текущую строку».
4. Явно заполнять и поля, подставившиеся по умолчанию.
5. В каждом создаваемом документе вводить служебный комментарий `ДокументСозданВСценарииАвтотестирования_<Тест>`.
6. В списке выделять документ одним щелчком, не открывая.
7. Лишние клики не исправлять; при ошибке по существу — начать запись заново.
8. Остановить запись, сохранить текст целиком без правок, записать время и замечания.

Практика PoC: даже с памяткой человек выбрал 4 значения через формы подбора «текущей строкой» и не ввёл комментарий. Памятка снижает число дефектов, но не отменяет доводку.

### Чек-лист доводки записи

| # | Дефект записи | Что сделать |
|---|---|---|
| 1 | `Контекст` с шагом подключения TestClient | удалить: клиент подключает профиль/MCP |
| 2 | `нажимаю кнопку выбора у поля` → форма подбора → `выбираю текущую строку` без перехода к строке | заменить на `из выпадающего списка с именем '…' я выбираю по строке "…"` + `я перехожу к следующему реквизиту` + `элемент формы с именем '…' стал равен "…"` (Q39, Q63) |
| 3 | То же в таблице (`нажимаю кнопку выбора у реквизита`, форма подбора номенклатуры) | `в таблице '…' из выпадающего списка с именем '…' я выбираю по строке "…"` |
| 4 | Заполнены поля, которых нет в тестплане (договор и т. п.), выбранные «текущей строкой» | удалить, если без них процесс проходит; иначе — детерминированное значение и допущение в отчёте |
| 5 | `активизирую поле` перед вводом | удалить (Q22) |
| 6 | Заголовки окон `"… (создание) *"` с пробелом перед `*` | `"… (создание)*"` — пробел перед завершающей `*` не проходит `check_syntax` (Q25) |
| 7 | Жёсткий номер или дата в заголовке окна (`"Документ 0000-000012 от *"`) | `"Документ * от*"` (Q24, Q79) |
| 8 | Двойное «Провести и закрыть», повторное открытие документа | схема Q79: `ФормаЗаписать` → `жду, что поле с именем 'Номер' перестанет быть пустым` → `ФормаПровестиИЗакрыть` → `жду закрытия окна "… * от*"` |
| 9 | Действие по текущей строке списка (создание на основании, пометка) | запомнить номер документа (`я запоминаю значение поля с именем 'Номер' как "…"`) и перейти к строке `| 'Номер' |` / `| '$Номер$' |`, **без** `выбираю текущую строку` (ловушка 6) |
| 10 | Модальные диалоги с кнопками `Button0`, `Button1` | по заголовку кнопки: `я нажимаю на кнопку 'Да'` (Q61) |
| 11 | Не введён служебный комментарий | добавить в каждый создаваемый документ; при вводе на основании комментарий не переносится — вводить повторно |
| 12 | Нет проверок | по каждому «Тогда» — проверка значения (раздел «Проверки») |
| 13 | Нет очистки данных прошлых запусков | блок очистки в начале сценария (раздел «Идемпотентность») |
| 14 | `#`-комментарии, плоский список шагов | группы `*` с отступом (Q35, Q102) |
| 15 | Шаги с `Пауза` | заменить ожиданием события (Q16, Q31) |
| 16 | ≥ 3 однотипных строк табличной части, заполненных построчно (повтор блока «Добавить → поля → завершаю редактирование») | свернуть в цикл по таблице Gherkin (шаблон в «Кнопки, поля, таблицы»); проверки строк — тем же циклом |

Шаги, записанные рекордером и не затронутые чек-листом (имена кнопок, закладок, колонок, команд меню), не менять: это подтверждённые данные формы.

## Режим 2. Исследование через MCP

Схема официальных инструкций VA (`docs/AI/examples`, ручной режим): **Исследователь** проходит процесс в UI и собирает данные формы, **Писатель** пишет сценарий по результату.

- **Исследователь.** Проверить и остановить незавершённую запись (`get_vanessa_automation_state`), включить `user_actions_recording`, пройти «Когда» инструментами `manage_command_interface`, `execute_form_actions` (до 10 действий за вызов), `manage_form_elements`, `get_object_attributes` (типы полей), `get_table_data` (наличие данных до ввода ссылочного значения). Результат — карта имён формы, модальные окна, где и как проверять каждое «Тогда», записанные шаги, раздел «Что изменено в базе».
- **Писатель.** Строить сценарий из записанных шагов по чек-листу доводки режима 1, далее — обязательный цикл завершения.
- **Запреты.** Не создавать вспомогательные данные, которых нет в «Дано» (фиксировать блокировку); не завершать процессы 1С; не закрывать клиент тестирования без команды; не искать файлы по всему диску.
- Мультиагентный конвейер VA (оркестратор + 7 субагентов, восстановление DT) рассчитан на Claude Code, Windows и файловую базу; брать из него идеи (независимое ревью, «доверять артефактам, а не отчёту»), а не весь конвейер.

## Режим 3. Черновик без MCP

Собрать сценарий по правилам и справочнику шагов, заголовки полей — из тестплана. В ответе обязательно: список допущений (имена полей и колонок, способ создания на основании, форматы чисел) и пометка «не прогонялся, рабочим не является». Предложить режим 1.

## Обязательный цикл завершения (режимы 1 и 2)

Выполняется через MCP VA (Claude Code или другой MCP-клиент на ПК с 1С):

1. `open_feature_file` (заодно инициализирует редактор: без открытой фичи `get_vanessa_automation_state` падает с `isCodeEditor`).
2. `check_syntax` → исправить все ошибки.
3. `run_scenario` (`reloadAndRun`) → `get_test_results`.
4. При падении — разобрать **только форму упавшего шага**: `get_form_analysis` (`format=buttons` / `elements` / `gherkin`), `get_form_element_data`, скриншот `get_window_screenshot_os`; исправить; `reloadAndRunFromLine` с упавшей строки (Q65, Q80). Не больше 2–3 итераций, затем — к человеку.
5. Финальный `reloadAndRun` с начала.
6. Повторный `reloadAndRun` без ручной очистки.
7. Проверка очистки по данным: `get_table_data` по видам документов — документы предыдущего прогона с служебным комментарием помечены на удаление, прочие не затронуты.
8. Независимое ревью (ниже).

Классифицировать падения: неизвестный шаг / неверное имя элемента / формат значения / логика-данные / окружение. Окружение (не подключён клиент, модальное окно от прошлого прогона) — не повод править сценарий.

## Независимое ревью

Выполнять отдельным проходом по готовому файлу, не полагаясь на отчёт автора.

**Механические проверки (grep по файлу):**
- есть `# language: ru`, `@tree`, `Функционал:`, `Сценарий:` без номера через пробел;
- 0 вхождений `В панели разделов`, `В панели функций`, `Пауза`, `Я подключаю TestClient`, `закрываю текущее окно`, `КонецЕсли`, `Контекст:`, `Переменные:`;
- 0 вхождений `" *"` перед закрывающей кавычкой заголовка окна;
- 0 вхождений `Тогда открылось окно "…" в течение` (несуществующий шаг);
- ≥ 1 `я закрываю все окна клиентского приложения` в начале;
- 0 `#`-комментариев внутри сценария (группы — `*`, пояснения — `//`);
- есть блок очистки и служебный комментарий в каждом создаваемом документе.

**Смысловые проверки:**
- каждому «Тогда» тестплана соответствует проверка значения или `// ВЫНОС`; открытие окна и ввод проверками не считаются;
- числа и количества проверяются точным отображаемым значением (`"1,000"`, `"100,00"`), не шаблоном `"1*"` — он пропускает 10 и 100 (Q78, Q9);
- каждое «Заполняем X» тестплана — действие, а не проверка значения по умолчанию;
- `выбираю текущую строку` — только в формах выбора; в форме списка документов этот шаг открывает документ (ловушка 6);
- тело каждого `Если` хотя бы раз реально выполнилось на прогоне (условие, которое всегда `Ложь`, — мёртвый код; в PoC так «работала» очистка);
- порядок очистки — обратный порядку создания документов (Q98);
- очистка — только в начале сценария, не в конце: до шагов в конце упавший сценарий не дойдёт;
- документ в списке ищется по сохранённому номеру (`$Номер$`), а не по реквизитам: помеченные на удаление документы прошлых прогонов остаются в списке и находятся поиском по реквизитам;
- в проверке отчёта через `содержит строки` нет строки общего итога: итог по всему отчёту (например, 301 при двух проверяемых позициях) сбивает при чтении; итог проверять только после отбора, когда он равен сумме проверяемых строк.

Вердикт только «корректен» / «некорректен» с перечнем нарушений и строк.

## Правила Turbo Gherkin (по БЗ VA и прогонам PoC)

**Структура файла**
- `# language: ru`, теги (`@tree`, для экспортных — `@ExportScenarios`), `Функционал:` (обязателен, один), необязательные «Как / Я хочу / Чтобы», `Сценарий:`.
- Имя сценария уникально в файле. Не отделять номер пробелом (`Сценарий 1` / `Сценарий 2` при вызове как подсценарий сливаются в один шаг с числовым параметром) — `Сценарий_1` (Q5).
- Секция `Контекст:` — не использовать по умолчанию; подготовку писать первой группой сценария. Секция `Переменные:` — только по явной просьбе пользователя (Q5, Q6).
- Группы шагов: строка `* Название`, вложенные шаги — с отступом глубже (табуляция или пробелы, не смешивать). Группа и её шаги на одном уровне — шаг вне группы, без ошибки (Q102).
- `//` — пояснение внутри сценария; `#` — не использовать для структуры.

**Параметры и кавычки**
- Строковый параметр — в `"…"` или `'…'`, взаимозаменяемы. Апостроф имеет приоритет: кавычки внутри `'…'` не экранируются (Q5). Конвенция (как в официальных шаблонах шагов): имена элементов и таблиц — `'…'`, значения — `"…"`; значение с кавычками — в `'…'` (`'Торговый дом "Комплексный"'`).
- Экранирование: `\"`, `\'`, `\|` в таблицах, `\\`, `\{ \}` при вычислении выражений.
- Число — без кавычек (номер переключателя/гиперссылки по порядку).

**Управляющие конструкции**
- Условие: `Если <любой шаг> Тогда`, тело — с отступом; `ИначеЕсли`, `Иначе`. **`КонецЕсли` не писать** (Q5). Если шаг-условие упал — результат `Ложь`. Перед `Если элемент "…" присутствует на форме` проверить существование элемента (Q68).
- Цикл по таблице Gherkin: `И для каждой строки таблицы я выполняю` + таблица (заголовок — имена переменных, в теле — `$Имя$`) + тело с отступом; `Тогда я продолжаю цикл` / `Тогда я прерываю цикл`. Отступ тела обязателен и не диагностируется (ловушка 3). Отличается от цикла по строкам таблицы формы из БЗ (`для каждой строки таблицы "ИмяТаблицы" я выполняю`).
- Когда цикл: ≥ 3 однотипных строк данных (табличная часть, набор проверок) — цикл по таблице Gherkin: данные тестплана видны одной таблицей, сценарий компактнее. 1–2 строки или строки с разным набором полей — явные шаги. Рекомендация БЗ Q5 «избегать циклов, где можно без них» направлена против логики в сценарии; цикл-«таблица данных» ей не противоречит. Цена цикла: `reloadAndRunFromLine` нельзя начать с середины тела, а в отчёте о падении видна строка шага, но не строка данных — при отладке падения можно временно оставить в таблице одну строку.
- Нестабильные, не всегда возникающие окна (например, предложение интернет-поддержки) — условием, а не безусловным шагом: `Если появилось окно с заголовком "…" в течение N секунд Тогда` + тело с отступом.
- `Попытка / Исключение` — не использовать по умолчанию; допустимо для негативной проверки доступности (Q13) с явной пометкой.
- Код встроенного языка в сценарии — только простой и только для подготовки данных, не для тестируемой логики (Q11, Q44). Инструкции AI-агента VA запрещают «Выполнить произвольный код» — отклонение фиксировать в отчёте.

**Переменные**
- Создать: `я запоминаю значение поля с именем '…' как "Имя"`, `Я запоминаю значение выражения '…' в переменную "Имя"`, `я запоминаю строку "…" в переменную "Имя"`.
- Использовать: `$Имя$` в любом параметре, включая ячейки таблиц Gherkin (ловушка 2). Глобальные — `$$Имя$$`, только при необходимости.
- При сохранении навигационной ссылки имя переменной — без `$`: `в переменную "Ссылка"`; при использовании — `"$Ссылка$"` (Q95).
- Локальные переменные удаляются после сценария и не переживают вызов экспортного сценария (ловушка 4).

**Окна и навигация**
- Раздел + функция — один шаг `И В командном интерфейсе я выбираю "Раздел" "Функция"` (Q43).
- После смены окна — `Тогда открылось окно "…"` (без ожидания) или `И я жду открытия окна "…" в течение N секунд`. **Шага `Тогда открылось окно "…" в течение N секунд` нет** — пример в БЗ Q23 ошибочен, `check_syntax` отклоняет.
- После закрытия — `И я жду закрытия окна "…" в течение N секунд` (Q24).
- Заголовок: список — во множественном числе, форма создания — `"… (создание)*"` (Q96). Завершающая `*` — **без пробела**, пробел перед ней — ошибка `check_syntax`; `*` внутри — любое число раз (Q25).
- Закрывать окно по заголовку, не `закрываю текущее окно` (Q46). Модальный «Данные были изменены. Сохранить изменения?» — `Тогда появилось предупреждение, содержащее текст "…"` + `я нажимаю на кнопку 'Да'/'Нет'` (Q72–Q74).

**Кнопки, поля, таблицы**
- Кнопки — по имени: `я нажимаю на кнопку с именем 'ФормаПровестиИЗакрыть'`; в таблице — `в таблице '…' я нажимаю на кнопку с именем '…'` (Q1). Кнопка на закладке — сначала `я перехожу к закладке с именем '…'` (Q10).
- Ссылочное поле — `выбираю по строке`, полным наименованием; перечисление — `выбираю точное значение` (Q39, Q78).
- Заполнение поля: действие → `я перехожу к следующему реквизиту` → `элемент формы с именем '…' стал равен "…"` (Q63). Фиксировать значение перед паузой (Q48).
- Таблица: `завершаю редактирование строки` — только после последнего поля строки (Q62).
- Заполнение табличной части циклом (имена таблицы, колонок и кнопки — из записи или интроспекции):
  ```
  	* Заполнение табличной части
  		И для каждой строки таблицы я выполняю
  			| 'Ссылка'       | 'Число1'  | 'Число2'  |
  			| '<значение 1>' | '<число>' | '<число>' |
  			| '<значение 2>' | '<число>' | '<число>' |
  			| '<значение 3>' | '<число>' | '<число>' |
  			И в таблице 'ИмяТаблицы' я нажимаю на кнопку с именем 'ИмяКнопкиДобавить'
  			И в таблице 'ИмяТаблицы' из выпадающего списка с именем 'ИмяКолонкиСсылка' я выбираю по строке "$Ссылка$"
  			И я перехожу к следующему реквизиту
  			И в таблице 'ИмяТаблицы' в поле с именем 'ИмяКолонкиЧисло1' я ввожу текст "$Число1$"
  			И в таблице 'ИмяТаблицы' в поле с именем 'ИмяКолонкиЧисло2' я ввожу текст "$Число2$"
  			И в таблице 'ИмяТаблицы' я завершаю редактирование строки
  ```
  В теле — без `активизирую поле` (Q22); ссылочное значение — `выбираю по строке` (Q39). Значения в таблице — в отображаемом формате, чтобы та же таблица годилась для проверок.
- Перед выбором строки — `перехожу к строке`; в форме выбора — затем `выбираю текущую строку` (Q26); в форме списка — не выбирать (ловушка 6).
- Флаги — `устанавливаю` / `снимаю`, не `изменяю` (Q21, Q67); в условии — `имеет значение "Да"` / `"Нет"` с учётом языка (Q66).
- Шаги проверки видимости и доступности проверяют флаги элемента, а не реальную видимость (Q13). Ошибка «Невидимый пользователю элемент…» — элемент реально скрыт или группа свёрнута: `я разворачиваю группу с именем '…'` (Q70).

**Проведение и создание на основании**
- Проведение без дальнейшей работы с формой: `ФормаПровестиИЗакрыть` + `жду закрытия окна` (Q29, Q79).
- Новый документ, нужен номер или ссылка: `ФормаЗаписать` → `я жду, что поле с именем 'Номер' перестанет быть пустым в течение 30 секунд` → запомнить номер или ссылку → `ФормаПровестиИЗакрыть` → `я жду закрытия окна "… * от*"`.
- После проведения из списка — `Тогда не появилось окно предупреждения системы` (Q40).
- Отложенное или фоновое проведение — отдельное ожидание: `И Я жду завершения выполнения всех фоновых заданий (Расширение)` или `И выражение внутреннего языка '…' стало Истинно в течение N секунд`.
- Создание на основании — кнопка или пункт подменю формы; имя берётся только из записи или интроспекции; индексы в именах кнопок хрупки при доработке конфигурации — отметить в допущениях.

**Ожидания**
- Ждать события, а не времени: `жду открытия/закрытия окна`, `жду, что поле … перестанет быть пустым`, `жду, что в таблице … количество строк будет`, `у элемента … я жду значения`, `жду, что табличный документ … заполнится данными`.
- `Пауза` — только если события нет; допустимая комбинация — `пауза 3` + `жду закрытия окна ""` (Q31).

## Проверки

- **Значение поля формы:** `Тогда элемент формы с именем '…' стал равен "…"`; если значение отличается от текста редактирования — `у элемента формы с именем '…' текст редактирования стал равен "…"` (Q75, Q76).
- **Строка таблицы:** `я перехожу к строке:` по ключевой колонке, затем `Тогда в таблице '…' поле с именем '…' имеет значение "…"` — точным отображаемым значением («1,000», «100,00»).
- **Строки таблицы циклом** (при ≥ 3 строках — та же таблица данных, что при заполнении; в таком виде ещё не прогонялся — подтвердить первым прогоном):
  ```
  		Тогда в таблице 'ИмяТаблицы' количество строк "равно" 3
  		И для каждой строки таблицы я выполняю
  			| 'Ссылка'       | 'Число1'  | 'Число2'  |
  			| '<значение 1>' | '<число>' | '<число>' |
  			...
  			И в таблице 'ИмяТаблицы' я перехожу к строке:
  				| '<Заголовок ключевой колонки>' |
  				| '$Ссылка$'                     |
  			Тогда в таблице 'ИмяТаблицы' поле с именем 'ИмяКолонкиЧисло1' имеет значение "$Число1$"
  			И в таблице 'ИмяТаблицы' поле с именем 'ИмяКолонкиЧисло2' имеет значение "$Число2$"
  ```
  Альтернатива без цикла — `таблица 'Товары' содержит строки:` + количество строк (Q27), если колонки проверяемой таблицы известны точно.
- **Количество строк:** `Тогда в таблице '…' количество строк "равно" N`.
- **Вся таблица:** `таблица '…' содержит строки:` или `стала равной:`; при нестабильном порядке строк — `содержит строки` + количество (Q27). Шаги проверки содержимого сбрасывают текущую строку на первую (ловушка 5).
- **Сообщения:** `Тогда в окне сообщений пользователю нет сообщений`; `в логе сообщений TestClient есть строки` (по шаблону — с `*`) (Q3).
- **Отчёт:** `я нажимаю на кнопку с именем 'СформироватьОтчет'` → ожидание заполнения → `Дано Табличный документ "ОтчетТабличныйДокумент" равен макету "Имя" по шаблону`. Эталон mxl — рядом с feature, снимается `save_table_document_to_file` (Q8, Q28, Q88–Q92). Числа в отчёте — в формате отображения (Q9). Регистры проверять через отчёты, а не напрямую (Q32). В `содержит строки` не включать общий итог отчёта; итог проверять отдельно после отбора по проверяемым позициям.
- **Шаблон `по шаблону`** — для заведомо меняющихся частей (даты, номера), не для чисел и количеств.

## Идемпотентность и тестовые данные

- Предусловия «Дано» — существующие в базе объекты; сценарий их не создаёт. Отсутствие данных — блокировка с перечнем, а не повод создать аналог.
- **Служебный комментарий** `ДокументСозданВСценарииАвтотестирования_<Тест>` в каждом создаваемом документе, включая документы, введённые на основании: комментарий не переносится (Q82).
- **Очистка в начале сценария, в обратном порядке создания** (сначала документы на основании, затем основания) (Q98).
- Штатный шаг `И я помечаю на удаление документы "Вид" содержащих комментарий "…" (Расширение)` на 8.5.1.1343 / VAExtension 1.32 при найденных документах падает с модальным окном «Значение содержит данные недопустимых типов» (пометка при этом ставится). - Для НСИ, которую сценарий должен создать сам: `И я проверяю или создаю для справочника "…" объекты:` (подготовка данных VA); имена — `"VA_" + Блок + Объект + дата`.

## Переиспользование и приёмы данных

- **Экспортные сценарии** для блоков, повторяющихся в нескольких файлах: файл с тегом `@ExportScenarios` над `Функционал:`; имя `Сценарий:` одновременно текст шага вызова, параметры — в кавычках в имени (`Сценарий: Я заполняю шапку заказа поставщику "Поставщик"`); вызов — тот же текст с реальным значением. Таблицы Gherkin передаются сразу после строки вызова в порядке их использования (`||` — пустая). Имена — уникальные в проекте (ловушка 1), данные вызванного сценария проверять внутри него (ловушка 4).
- **Документ как подготовка данных** (не предмет теста): создать непроведённым, затем провести по той же ссылке — движения формируются корректно. Для теста движений — загружать готовый документ, а не создавать через UI.
- **Сравнение табличных частей** — вложенные циклы: внешний по строкам, внутренний по реквизитам, имя переменной `$Реквизит$_$НомерСтроки$`; известные расхождения формата — условием внутри цикла.
- **Выражения встроенного языка в шагах** (`Я запоминаю значение выражения '…' в переменную "…"`): `Формат(X, "ЧДЦ=2")`, `Окр`, `СокрЛП`, `СтрЗаменить`, `Формат(ТекущаяДата(), "ДФ=дд.ММ.гггг")`, `ДобавитьМесяц`, `НачалоДня`.
- Вспомогательные объекты подготовки данных отдельными проверками не покрывать — проверяется только предмет теста.

## Известные ловушки движка VA

1. Дубль имени экспортного сценария не диагностируется — только «Не найдена процедура…» при выполнении. Имена экспортных сценариев — уникальные в проекте.
2. Подстановка переменной — только `$Имя$`; совпадение имени со строкой параметра не работает и не диагностируется.
3. Тело `Если` / цикла без отступа выполняется один раз как обычные шаги, без ошибки.
4. Локальные переменные не переживают вызов экспортного сценария; проверку данных вызванного сценария размещать внутри него.
5. Шаги проверки содержимого таблицы (`содержит строки` и подобные) сбрасывают текущую строку на первую.
6. `выбираю текущую строку` в форме выбора возвращает значение, в форме списка документов — открывает документ. Для позиционирования достаточно `перехожу к строке`.
7. Рекордер записывает заголовки `"… *"` с пробелом, которые `check_syntax` не принимает.
8. Пример БЗ Q23 `Тогда открылось окно "…" в течение 10 секунд` — несуществующий шаг. Пример БЗ Q102 использует двухшаговую панель разделов/функций, которую Q43 объявляет неправильной.
9. Рекордер при выборе через форму подбора пишет `выбираю текущую строку` без перехода — выбранное значение по записи не восстановить.

## Инструменты MCP VA (для режимов 1–2)

Сервер: расширение `client_mcp` (onec-client-mcp-devkit) в базе менеджера тестирования, запуск `/C "runMcp=<json>"` или `runMcp;mcpPort=<порт>`, адрес `127.0.0.1`, без аутентификации; клиент — Claude Code (`.mcp.json` с `{"type":"http","url":"http://localhost:<порт>/mcp"}`). 38 инструментов = 37 VA + `infobase_info`.

- Состояние: `get_environment_data`, `get_vanessa_automation_state` (после `open_feature_file`), `get_extension_list`, `manage_test_client`, `manage_test_client_profiles`.
- Шаги и правила: `get_data_from_knowledge_base` (`format=all`; большой ответ — читать из сохранённого файла), `search_for_steps_by_keywords`, `frequently_used_steps`, `check_syntax`.
- Форма и данные: `get_form_analysis` (`format=elements` / `buttons` / `gherkin`), `get_form_element_data`, `get_object_attributes`, `get_table_data`, `manage_command_interface`, `get_active_window_data`, `get_window_list_testclient`, `get_window_screenshot_os`.
- Действия: `execute_form_actions`, `manage_form_elements`, `window_management`, `user_actions_recording`, `save_table_document_to_file`.
- Прогон: `open_feature_file`, `load_features`, `run_scenario` (`reloadAndRun`, `reloadAndRunFromLine` + `lineNumber`), `get_test_results`, `stop_scenario`.

Менеджер и клиент тестирования — предпочтительно в разных информационных базах: менеджер стартует быстрее, а восстановление базы клиента из DT (мультиагентный конвейер VA) без этого невозможно. `client_mcp` — в базе менеджера, VAExtension — в базе клиента; в обоих снять защиту от опасных действий и безопасный режим. Промпты VA из `docs/AI` при использовании в не-ERP конфигурации — заменить упоминания ERP на свою конфигурацию, иначе строгие модели отказываются работать.

Особенности: в `execute_form_actions` закладка указывается внутренним именем группы (`ГруппаОсновное`), а `navigate_to_row` — заголовком колонки («Номер»); числовые поля таблицы — `input_text`, не `set_value`; перед `select_from_dropdown` — `open_dropdown`. После переподключения MCP-сервера клиент тестирования может быть отключён — `manage_test_client(connect)`.

## Формат ответа

1. Готовый `.feature`.
2. Таблица правок: дефект → исправление; для режима 1 — по чек-листу доводки.

5. Статус: «прогнан, ревью пройдено» или «не прогонялся» — без третьих вариантов.
