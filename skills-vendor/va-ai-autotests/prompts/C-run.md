# Вариант C+, этап «Прогон»

Новая сессия Claude Code, MCP VA подключён, запись действий запрещена (см. docs/install.md). Перед прогоном — база в исходном состоянии.

```
Вариант C+, этап «Прогон». Работай в текущем каталоге. Клиент тестирования подключён, НЕ закрывай его и не завершай процессы 1С.
Файл сценария: 01_Заказ_поставщику_Приобретение_ТиУ.feature (подготовлен по записи рекордера и skill). Входы: ТестПлан.MD, C_notes.md (допущения автора сценария).

1. Сохрани копию 01_v0.feature. open_feature_file + check_syntax, запиши число ошибок; исправь только синтаксис.
2. run_scenario (reloadAndRun) → get_test_results.
3. Итерации исправления — максимум 2. При падении разрешено ТОЧЕЧНО разобрать форму упавшего шага: get_form_analysis (format=buttons/elements), get_form_element_data, get_object_attributes, скриншот. Запрещены user_actions_recording и повторное исследование процесса целиком. Лишние окна закрывай через window_management. Документы в базе вручную не правь.
4. После зелёного прогона — ещё один reloadAndRun без ручной очистки (идемпотентность). Затем get_table_data по документам ЗаказПоставщику и ПриобретениеТоваровУслуг (последние 10): проверь, помечены ли на удаление документы прошлых запусков с комментарием «ДокументСозданВСценарииАвтотестирования_Тест01».
5. Результат в C_result.md:
   - время начала и окончания, число вызовов инструментов;
   - таблица прогонов: итерация, упавшая строка, причина, классификация (неизвестный шаг / неверное имя элемента / формат значения / логика-данные / окружение), исправление;
   - итог (зелёный или нет);
   - сработала ли очистка (пункт 4);
   - diff итогового feature относительно 01_v0.feature.
Если клиент тестирования отключится, переподключи его через manage_test_client — это окружение, итерацией не считается.
```
