# Вариант A, этап «Прогон»

Новая сессия Claude Code, MCP VA подключён. Интроспекция формы, поиск шагов и база знаний запрещены в настройках (см. docs/install.md): вариант A исправляется только по тексту ошибки.

```
Вариант A. Работай в текущем каталоге. Клиент тестирования уже подключён, НЕ закрывай его.
Разрешённые инструменты VA: open_feature_file, check_syntax, run_scenario, get_test_results, get_window_screenshot_os (только чтобы описать ошибку). ЗАПРЕЩЕНО: get_form_analysis, get_object_attributes, get_table_data, manage_form_elements, execute_form_actions, user_actions_recording, search_for_steps_by_keywords, frequently_used_steps, get_data_from_knowledge_base — вариант A исправляется только по тексту ошибки.

1. open_feature_file + check_syntax для 01_Заказ_поставщику_Приобретение_ТиУ.feature. Сохрани исходный файл копией 01_v0.feature до любых правок. Запиши число ошибок синтаксиса.
2. run_scenario (mode=reloadAndRun), затем get_test_results. Запиши: номер строки и текст упавшего шага, текст ошибки.
3. Итерации исправления: максимум 2. Правь feature только исходя из текста ошибки и своих общих знаний VA. После правки — run_scenario (можно reloadAndRunFromLine с упавшей строки). Перед правками закрывай лишние окна через window_management.
4. Результат в A_result.md: таблица прогонов (итерация, упавшая строка, причина, классификация: неизвестный шаг / неверное имя элемента или заголовка / логика-данные / другое), итог (зелёный или нет), время, сколько value-проверок из 5 пунктов «Тогда» тестплана реально выполнилось, и diff итогового feature относительно 01_v0.feature.

Уточнения: исправление синтаксиса до первого прогона и сбои подключения клиента итерациями не считаются; лимит 2 итерации — только на исправления по ошибкам выполнения сценария. Skill на этом этапе не используй — только текст ошибки.
Если клиент тестирования отключится, переподключи его через manage_test_client — это окружение, итерацией не считается.
```
