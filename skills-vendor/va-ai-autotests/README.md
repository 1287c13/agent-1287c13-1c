# AI-автотесты Vanessa Automation для 1С: три подхода

Проверка концепции: как получить рабочий автотест [Vanessa Automation](https://github.com/Pr-Mex/vanessa-automation) с помощью AI-агента (Claude Code) на живой 1С:ERP. Одна задача, одна модель, три подхода.

🎬 Ролик: [AI-автотесты Vanessa Automation на 1С:ERP: skill, агент VA через MCP или запись + доводка](https://youtu.be/117BaTwUhmI)

## Итог

Лучший результат дала связка «две минуты записи рекордером человеком + доводка по skill»: зелёный тест с первого прогона. Без формы перед глазами агент не угадывает имена элементов; полностью автономный агент находит их сам, но дольше и без человека не обходит проблемы окружения.

| Показатель | A · skill без формы | B · агент-исследователь VA | C+ · запись + доводка по skill |
|---|---|---|---|
| Результат | не зелёный, шаг 55 из 68 | не зелёный, упал на дефекте VA [#2717](https://github.com/Pr-Mex/vanessa-automation/issues/2717) | **зелёный, 75 из 75** |
| Время человека | 0 | 0 | ≈ 2 мин (запись) |
| Время агента | ≈ 3 мин | ≈ 17 мин | ≈ 3,5 мин |
| Итерации исправлений | 2, не хватило | 3, не хватило | 0 |
| Проверки «Тогда» | 1 из 5 | 0 из 5 | 5 из 5, точные значения |
| Повторный прогон | не проверялся | не дошёл | зелёный, очистка подтверждена по данным |

Условия: процесс «Заказ поставщику → Приобретение товаров и услуг», демо-база 1С:ERP, платформа 8.5.1.1343, Vanessa Automation 1.2.043.42, MCP-сервер VA через [onec-client-mcp-devkit](https://github.com/1c-neurofish/onec-client-mcp-devkit) client_mcp 0.6.5, VAExtension 1.32, Claude Code (VS Code), Sonnet, уровень рассуждений High. A и C+ — на одной версии skill (этой). B — по официальным промптам VA из `docs/AI`. Повторы от 04.10.2026.

Подробности по каждому варианту — в `example/results/<A|B|C>`: исходная и итоговая фичи; для A и C+ — отчёты агента, для B — результат исследования (разбор прогона B — в ролике).

## Что внутри

| Путь | Что это |
|---|---|
| `skill/va-scenario-generator/SKILL.md` | skill для Claude: правила Turbo Gherkin по БЗ VA, чек-лист доводки записи рекордера, независимое ревью, справочник шагов, приём очистки данных |
| `skill/va-scenario-generator/erp-demo-notes.md` | справка по формам 1С:ERP с демо-базы — не часть skill, подключайте по необходимости |
| `prompts/` | промпты всех этапов: A (генерация, прогон), B (исследователь, писатель), C+ (доводка, прогон) |
| `example/` | тестплан, сырая запись рекордера, результаты трёх вариантов |
| `docs/install.md` | как подключить skill и MCP VA к Claude Code, настройки разрешений по этапам |

## Быстрый старт

1. Подключите skill и MCP VA по `docs/install.md`.
2. Напишите тестплан в формате Дано / Когда / Тогда (пример — `example/ТестПлан.MD`).
3. Запишите процесс рекордером VA по памятке из skill (раздел «Памятка для записи»).
4. Доводка: `prompts/C-finish.md`. Прогон: `prompts/C-run.md`.

## Ограничения

- Один процесс, одна модель, по одному прогону на вариант. Токены не измерялись.
- Skill не заменяет человека: решение «баг или ожидаемое поведение» при падении теста остаётся за ним.
- Менеджер и клиент тестирования на стенде были в одной базе; для мультиагентного режима VA их нужно разводить.
- Статус: экспериментальная версия по итогам проверки. Замечания и issue приветствуются.

## Найденное в самой VA

- [#2717](https://github.com/Pr-Mex/vanessa-automation/issues/2717) — шаг пометки на удаление по комментарию (Расширение) на 8.5 падает с «Значение содержит данные недопустимых типов». Обход — серверный код через VAExtension (есть в skill).
- [#2719](https://github.com/Pr-Mex/vanessa-automation/issues/2719) — `check_syntax` в MCP отклоняет заголовок `"… (создание) *"`, который пишет рекордер и принимает сам VA.
