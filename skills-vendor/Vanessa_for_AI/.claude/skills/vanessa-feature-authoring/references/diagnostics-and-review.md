# Диагностика и финальная проверка

## Разбор ошибки

1. Выдели фактический шаг, ожидаемое состояние и наблюдаемое состояние.
2. Определи класс причины: неизвестный шаг, неверный UI-факт, неверный переход окна, race condition, область переменной, данные или очистка.
3. Считай техническую диагностику более свежим источником, чем неподтверждённое предположение.
4. Исправь минимальную причину и сохрани бизнес-проверку.
5. Не превращай обязательное действие в условное только для зелёного результата.

## Независимые доказательства результата

- Повторное открытие доказывает сохранение, но не проведение.
- Поле статуса доказывает статус, но не обязательно движения.
- Наличие движения в регистре проверяй отдельным утверждением.
- Успешное завершение экспортного сценария не доказывает корректность вызывающего wrapper.

## Финальный обзор

- Сопоставь итоговый файл с последней записью пользователя.
- Перечисли намеренные отличия и их доказательства.
- Проверь все затронутые экспортные зависимости.
- Проверь трассу окон и границы ожиданий.
- Проверь порядок очистки.
- Синхронизируй ближайший README только с фактическими проверками.
- Явно укажи: runtime выполнен, не выполнен или завершился конкретной ошибкой.
