# Состояния окон и ожидания

## Трасса состояния

Для каждого действия, способного сменить окно, зафиксируй:

```text
действие -> ожидание подтверждённого постусловия -> активное окно -> последующее чтение данных
```

Особенно проверяй переходы после:

- открытия навигационной ссылки;
- записи и проведения;
- записи и закрытия;
- выбора из отдельной формы;
- переключения вкладки;
- подтверждения модального окна.

## Асинхронные действия

Считай запись, проведение, закрытие и модальные подтверждения асинхронными, пока runtime не доказал обратное.

После команды:

1. жди наблюдаемое постусловие;
2. утверждай ожидаемое состояние;
3. только затем сохраняй ссылку, заголовок или значение.

Предпочитай условные ожидания фиксированным паузам. Если стабильное постусловие неизвестно, запроси запись и техническую диагностику от действия до стабилизированной формы.

## Заголовки

`ЗаголовокАктивногоОкна` из runtime-ошибки является сильным доказательством фактического состояния.

- `"Префикс *"` требует пробел перед wildcard.
- `"Префикс*"` не требует пробел.
- Используй точный наблюдаемый заголовок, если он стабилен.

Старое значение при уже новом окне обычно означает race condition. Исправь границу ожидания, а не парсер значения.
