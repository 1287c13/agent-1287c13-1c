# Авторинг сценариев Vanessa Automation

Не подключай MCP. Работай с файлами проекта, локальным каталогом шагов, записью пользователя и runtime-диагностикой.

## Проверь вход

До изменения UI-шагов получи:

1. бизнес-цель;
2. ожидаемые проверки результата;
3. запись Vanessa Automation либо runtime-проверенный аналог.

Если структуры проекта нет, сначала используй `vanessa-project-bootstrap` и дождись согласования. Если не подтверждена конкретная UI-деталь, запроси минимальный фрагмент записи или диагностики до редактирования затронутых шагов.

## Собери контекст

1. Прочитай `AGENTS.md`, корневой README и ближайший README сценария.
2. Найди похожие исполняемые и экспортные сценарии.
3. Проверь точные имена вызываемых `@ExportScenarios`.
4. Определи версию Vanessa Automation и подходящий каталог шагов.
5. Составь порядок зависимостей и очистки.

## Спроектируй сценарий

1. Отдели подготовку, действие, независимые бизнес-проверки и очистку.
2. Для каждого действия, меняющего окно, запиши трассу:

   `действие -> ожидаемое активное окно -> источник факта`

3. После асинхронных действий добавь ожидание подтверждённого постусловия до чтения заголовка, ссылки или значения.
4. Передай все зависимости экспортного сценария явными параметрами.
5. Проверяй сохранение, проведение и бизнес-статус раздельно.

## Выбери шаги

1. Сначала сохрани формулировки из записи или runtime-проверенного аналога.
2. Ищи каталог точечно через `rg`; не загружай весь JSON в контекст.
3. Сверь сигнатуру и параметры шага с версией пользователя.
4. Не считай шаг из встроенного fallback гарантированно доступным в другой версии или с другим набором библиотек.
5. Не заменяй один способ взаимодействия другим без runtime-доказательства.

## Проверь перед передачей

- Синтаксис, кодировку, язык и отступы.
- Все изменённые wrappers и их `@ExportScenarios` вместе.
- Существование каждого межфайлового вызова.
- Каждое `$...$` и `$$...$$` относительно границ экспортного вызова.
- Ожидания после записи, проведения, закрытия и модальных действий.
- Условные действия вложены на один уровень, а первый безусловный шаг после блока возвращён на уровень `Если`.
- Перед ожидаемой ошибкой очищены сообщения, а текст ошибки и постусловие проверены независимо.
- Независимые утверждения бизнес-результата.
- Обратный порядок очистки и отсутствие путаницы между удалением переменной и объекта 1С.
- Соответствие ближайшего README фактически реализованным проверкам.

## Передай runtime-цикл пользователю

Сообщи, что изменено, какие факты использованы и какие детали остались неподтверждёнными. Явно напиши, выполнялся ли runtime-прогон. После ошибки используй техническую диагностику как новый источник, исправляй минимальную причину и не маскируй обязательные проверки условиями.
