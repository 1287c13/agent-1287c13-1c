# Проверка и согласование структуры

## Сначала обнаружить

- Корень Git и рабочий каталог агента.
- Существующие `AGENTS.md`, `CLAUDE.md`, README и локальные правила.
- Все `.feature` и каталоги `step_definitions`.
- Параметры запуска Vanessa Automation, пути загрузки фич и библиотек.
- Использование `@ExportScenarios`, `Контекст`, хуков и файлов тестовых данных.
- Нумерацию каталогов и фактический порядок исполнения.
- Принятые префиксы генерируемых данных и переменных.
- Текущую стратегию очистки и повторного запуска.

Не спрашивай пользователя о факте, который однозначно подтверждён файлами.

## Уточнить в чистом проекте

1. Где Vanessa Automation будет искать исполняемые `.feature`.
2. Нужен ли отдельный каталог экспортных сценариев и как он подключается.
3. Как группировать первый сценарий: бизнес-область, объект, операция.
4. Нужна ли числовая сортировка каталогов.
5. Какой префикс использовать для генерируемых данных.
6. Какие записи допустимо оставлять, помечать на удаление или удалять.
7. Должны ли сценарии запускаться независимо и в произвольном порядке.
8. Какая конфигурация 1С, язык UI и версия Vanessa Automation используются.

## Минимум при делегированном выборе

Если пользователь не задаёт структуру, предложи:

```text
features/
└── <БизнесОбласть>/
    └── <Объект>/
        ├── README.md
        └── <Операция>.feature
```

Добавляй `features/90_Библиотека/` только когда первый сценарий действительно требует переиспользуемой зависимости. Не создавай каталоги НСИ, документов, регистров или очистки без текущей потребности.

## Содержание README объекта

- назначение сценариев;
- подтверждённая навигация и заголовки окон;
- способы поиска и выбора;
- обязательные исходные данные;
- стратегия создания и очистки;
- версия конфигурации и Vanessa Automation;
- дата и результат последнего runtime-прогона.

Не добавляй неподтверждённые UI-факты как окончательные правила.
