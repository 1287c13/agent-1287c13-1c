# 2. ПМИ — ტესტირების პროგრამა და მეთოდიკა

*ГОСТ-ის ფორმალური სტრუქტურა. უნდა ფარავდეს **ТЗ-ის ყველა ფუნქციურ და არაფუნქციურ მოთხოვნას** მოსალოდნელი შედეგით. დამკვეთისთვის ეს ბოლო შესაძლებლობაა, გავლენა მოახდინოს სისტემის მახასიათებლებზე — ეს პირდაპირ უნდა ითქვას მას.*

1. **ტესტირების ობიექტი** — სისტემის დასახელება, კომპლექტურობა, ტექნიკური საშუალებების მოთხოვნები
2. **ტესტირების მიზანი** — ამოცანები და **შესამოწმებელი თვისებების ჩამონათვალი**
3. **ზოგადი დებულებები** — ხელმძღვანელი დოკუმენტები, ადგილი, ხანგრძლივობა, მონაწილე ორგანიზაციები
4. **ტესტირების მოცულობა** — ეტაპები, მახასიათებლების გეგმიური მნიშვნელობები, მუშაობის რეჟიმები
5. **პირობები და ჩატარების წესი** — დაწყებისა და დასრულების პირობები, პერსონალის მოთხოვნები
6. **მატერიალურ-ტექნიკური უზრუნველყოფა** — ინფრასტრუქტურა და პასუხისმგებლობის განაწილება
7. **მეტროლოგიური უზრუნველყოფა** — გაზომვის საშუალებები
8. **ანგარიშგება** — აქტები, ანგარიშები, გაფორმების ვადები
9. **დანართები** — **მეთოდიკები შემოწმების ნაბიჯების თანმიმდევრობით**

**გამომავალი დოკუმენტები:** ტესტირების პროტოკოლები · ტესტირების აქტი (დასკვნა მზაობის/არამზაობის შესახებ) · მიღების ტესტირების ერთიანი პროტოკოლი.

**მიღების კომისიის შემადგენლობა:** ფუნქციური დამკვეთები · ქვედანაყოფების წარმომადგენლები (ძირითადი მომხმარებლები) · ტექნიკური სამსახურების წარმომადგენლები.
