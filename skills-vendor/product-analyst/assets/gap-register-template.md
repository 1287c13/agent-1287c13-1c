### სვეტების ლეგენდა

**ვერდიქტი**
- `FIT` — ტიპური ფუნქციონალი ფარავს
- `FIT პროცესის ცვლილებით` — ფარავს, თუ ბიზნეს-პროცესს მოვარგებთ ტიპურს *(ყოველთვის განიხილე პირველად)*
- `GAP` — საჭიროა პარამეტრიზაცია ან შემუშავება

**RICEFW + S**

*RICEFW — ERP-ის სტანდარტული სქემა (ასევე RICEF ან WRICEF); **S** ემატება 1C-სთვის, სადაც სამუშაოს დიდი ნაწილი წმინდა პარამეტრიზაციაზე მოდის.*

| კოდი | რა არის | როგორ ხორციელდება 1C-ში |
|---|---|---|
| **S** | System configuration — პარამეტრიზაცია | ფუნქციონალური ოფციები, აღრიცხვის პარამეტრები, დამატებითი რეკვიზიტები და ცნობები, წვდომის ჯგუფების პროფილები, ანგარიშის ვარიანტები, ფასწარმოქმნის წესები, რეგლამენტური დავალებები |
| **R** | Report — ანგარიში | ტიპური ანგარიშის ვარიანტი → გარე ანგარიში (.erf) БСП-ით → ანგარიში გაფართოებაში → ანგარიში კონფიგურაციაში |

| **C** | Conversion — მიგრაცია | „მონაცემთა კონვერტაცია" 2.1/3.0, გარე დამუშავებები |

| **W** | Workflow — შეთანხმება და მარშრუტიზაცია | ბიზნეს-პროცესები და ამოცანები, БСП-ის შეთანხმება, მარშრუტები 1С:ДО-ში |

| 6 | მხარდაჭერიდან სრული მოხსნა | ავტომატური განახლება შეუძლებელია |

*3-დან ქვემოთ თითოეული ნაბიჯი ზრდის **ყოველი მომავალი განახლების** ღირებულებას. დონეები 4 და 5 ერთსა და იმავე მხარდაჭერის რეჟიმში ათავსებს — განსხვავება ისაა, თუ რამდენ ტიპურ ობიექტს ეხები ხელით: შეცვლილი ტიპური ობიექტი ყოველ რელიზზე ხელით შედარებას და გაერთიანებას ითხოვს, ახალი საკუთარი ობიექტი — არა. ეს არის წინადადება, რომელიც ხმამაღლა უნდა ითქვას შეხვედრაზე.*

**შრომატევადობა (PERT)**
`E = (O + 4M + P) / 6` · `σ = (P − O) / 6` · `პროექტის ბუფერი = ΣE + 2·√(Σσ²)` (გადახრები კვადრატულად ეჯამება, და არა წრფივად) · `CV = σ / E` — თუ **CV > 20%**, შეფასება გადასახედია, და არა ბუფერის გასაზრდელი.
*პესიმისტური შეფასება აიგება **დოკუმენტირებულ რისკებზე**, და არა ზოგად პესიმიზმზე.*

## გაფართოებების რეესტრი

*თუ პროექტში გაფართოებები გამოიყენება, ცალკე რეესტრი სავალდებულოა — წინააღმდეგ შემთხვევაში წელიწადში მათი შემადგენლობა აღარავინ იცის.*

| გაფართოება | დანიშნულება | რა ობიექტებია ნასესხები | პერეხვატის ტიპი (перехват) | ხარვეზები (G-ID) | რისკი | პასუხისმგებელი |
|---|---|---|---|---|---|---|
| | | | `&Перед` / `&После` / `&ИзменениеИКонтроль` / `&Вместо` | | | |

**რისკები, რომლებიც სავალდებულოდ უნდა იყოს რისკების რეესტრში:**
- **გაფართოების წაშლისას მასში შენახული მონაცემები უკუქცევადად იკარგება** (გამორთვა ინახავს, წაშლა — არა)
- `&Вместо` ქმნის თავსებადობის პრობლემებს განახლებისას — უპირატესობა `&Перед` / `&После` / `&ИзменениеИКонтроль`-ს
- გაფართოებაში ფორმის ცვლილებები განახლებისას **გაფრთხილებას არ იძლევა** — „ჩუმი" ჩავარდნა
- განახლების შემდეგ მომწოდებელმა შეიძლება შეცვალოს ობიექტები, რომლებზეც გაფართოება დგას
- გაფართოებაში მონაცემების შენახვა უარესია წარმადობით, ვიდრე ძირითად კონფიგურაციაში
- ბევრი მცირე გაფართოება არაპროპორციულად ართულებს ადმინისტრირებას — გააერთიანე დაკავშირებული ცვლილებები
