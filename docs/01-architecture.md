# Архитектура стека

## Три независимых слоя

| Слой | Задача | Компонент | Зависит от публикации / COM |
|---|---|---|---|
| 1. Код и метаданные | «смотреть код конфигурации» | `code-index-mcp` (bsl-indexer) по XML-выгрузке | нет |
| 2. Живая база | «выполнять запросы» | `1c-mcp-toolkit` — HTTP-сервер внутри `.epf` | нет |
| 3. Запуск платформы | «запускать 1С» и операции с базой | вендорские скиллы `db-*` над `1cv8.exe` / `1cv8c.exe` | нет |

### Почему именно так

* Код конфигурации читается **только** из разобранной конфигурации (XML из
  Конфигуратора или `.mdo` из EDT). Публикация базы коду не помогает, поэтому
  слой 1 обязателен и не зависит от инфраструктуры.
* Запросы к данным требуют канала. Вариант «HTTP-сервер в `.epf`» снимает
  необходимость публиковать базу на IIS/Apache и настраивать COM.
* Ни один MCP-сервер не умеет запускать платформу, поэтому слой 3 — это
  вендорские скиллы (`db-*`, `cf-*`, `cfe-*`) поверх командной строки 1С.

## Опциональные модули (лежат выключенными)

| Модуль | Когда включать |
|---|---|
| `feenlace/mcp-1c` | если база публикуется на IIS/Apache: один бинарник, live-метаданные + SELECT-запросы |
| `prepod2003/mcp-rsv-data` | для аналитика: строго read-only + обезличивание ПДн по COM (Windows) |
| `1c-syntax/bsl-language-server` | проверка синтаксиса и навигация (нужна JVM) |

## Поток данных

```
XML-выгрузка  ──►  code-index-mcp  ──►  структура, код, связи, права
                                                        │
Живая база  ──►  1c-mcp-toolkit (.epf) ──►  метаданные + данные + запросы
                                                        │
1cv8.exe / 1cv8c.exe ──► скрипты ──► создание/обновление базы, dump/load, запуск
                                                        ▼
                                                      Cline
```
