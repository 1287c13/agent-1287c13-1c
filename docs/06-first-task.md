# Как дать агенту первую задачу

## 1. Перед первой задачей (один раз)

Заведите `docs\context.local.md` и опишите в нём базу: тип (файловая/КС), путь или
сервер, учётку, права, что можно и чего нельзя, где лежит выгрузка. Этот файл
читается как контекст задачи.

## 2. Чем давать задачу

Пишите задачу текстом: что нужно, где (объект метаданных / папка), текущее и
ожидаемое поведение, как проверить.

* аналитика — бизнес-вопрос, период, разрез, критерий сверки;
* разработка — что сделать, где, как проверять (валидация скиллом, ручной сценарий, тест).

Минимум, без которого задача превращается в угадывание: **объект/период** и
**критерий проверки**.

## 3. Первая задача аналитика (пример)

```
Роль: 1С-аналитик.
База: из docs\context.local.md.
Задача: остатки номенклатуры по складам на 01.10.2026, вывести 20 строк с
наибольшим остатком в сумме, только чтение.

Проверка: сверю с отчётом «Остатки товаров на складах» в 1С за тот же период.
```

Ожидаемый ход: разведка метаданных (регистр остатков, измерения, ресурсы) →
запрос → таблица/CSV → сверка.

## 4. Первая задача разработчика (пример)

```
Роль: 1С-разработчик.
Задача: в Документ.РеализацияТоваровУслуг добавить реквизит «НомерЭДО» (Строка 36)
и вывести его на форму. Оформить расширением .cfe, основную конфигурацию не менять.

Шаги: выгрузить XML → правка XML/модулей → синтаксический контроль → загрузка
расширения → UpdateDBCfg расширения → проверка.
Не делать UpdateDBCfg основной конфигурации без моего подтверждения.
```

Ожидаемый ход: найти объект в индексе → структура объекта и формы → правка →
валидация вендорскими скиллами (`meta-validate` / `cfe-validate`) → сборка и загрузка
расширения (`cfe-init`, `db-update`) → отчёт с diff.

## 5. Как ограничить меня

* «только чтение» — я не выполняю изменения данных и конфигурации;
* «не трогать основную конфигурацию» — работаем расширением `.cfe`;
* «не делать UpdateDBCfg» — только выгрузка/правки/проверка;
* «обезличивать ПДн» — заменяю ФИО/ИНН/телефоны на плейсхолдеры в ответах.

Пропишите это в `docs\context.local.md`, и я буду соблюдать по умолчанию.

## 6. Как проверить результат

* аналитика — сверка с отчётом конфигурации за тот же период;
* разработка — валидация вендорскими скиллами (`meta-validate`, `cfe-validate`), ручной сценарий по шагам из ТЗ, при
  наличии — тест (YAxUnit/Vanessa);
* всегда — diff файлов и лог запуска из `logs\`.
