# Диагностика

## MCP: Cline не видит инструменты

| Признак | Причина и что делать |
|---|---|
| Инструментов нет вообще | Сервер не запущен или Cline не перезапущен после правки конфига. Перезапустите Cline и проверьте JSON |
| `daemon_offline` | Не запущен демон `bsl-indexer daemon run`, либо у демона и сервера разные `CODE_INDEX_HOME` |
| `not_started` («путь не отслеживается демоном») | Папки нет в `daemon.toml`. Добавьте `[[paths]]` и выполните `bsl-indexer daemon reload` |
| `unknown_repo` | Клиент указал алиас, которого нет в `daemon.toml` (у нас `ar208`) |
| `os error 10048` (адрес занят) | Порт 8011/8015 занят другой копией. Поменяйте порт в `daemon.toml` и в конфиге Cline |
| Индекс есть, но пусто | Демон ещё индексирует. Смотрите `mcp\code-index-mcp\daemon.log`, ждите статус `[ready]` |

## 1С: пакетный режим

| Признак | Причина и что делать |
|---|---|
| «Не найдена платформа» | Неверный путь к платформе в конфиге вендорских скиллов (`.v8-project.json`) — см. `skills-vendor\cc-1c-skills\docs\v8-project-guide.md` |
| Требует логин/пароль | Впишите учётку базы в `.v8-project.json` (этот файл держите вне git) |
| `UpdateDBCfg` падает по блокировке | Нужен эксклюзивный режим: закройте сеансы (Конфигуратор, пользователи) |
| Ошибка «Конфигурация не поддерживается» | Для объектов на поддержке правки ограничены — работайте через расширение `.cfe` (скиллы `cfe-*`) |
| Логи пустые | Платформа пишет `/Out`-лог в конце; скиллы кладут логи рядом с рабочей папкой — ищите по свежим файлам |

## Русский текст в скриптах превратился в мусор

Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI. Лечится:

```powershell
.\scripts\fix-encoding.ps1
```

Запускать после каждой правки `.ps1` в стороннем редакторе.

## Слой живой базы (1c-mcp-toolkit)

| Признак | Что делать |
|---|---|
| «Запрос не выполнен» | Не запущен `MCP_Toolkit.epf` в режиме «Встроенный сервер», либо другой порт |
| Пустой результат | Не включён состав OData/объекты, либо прав у пользователя нет |
| Долго | Латентность базы: сузьте период и добавьте условия |
| Неясно, как вызвать | Скилл `calling-1c-rest-api-via-curl` (REST `/api/*`) и `composing-1c-queries` (текст запроса) |

## Выгрузка, индекс, диск

| Признак | Причина и что делать |
|---|---|
| `WARN parse_configuration_file ... tag not closed` в `daemon.log` | Выгрузка обрезана — обычно кончилось место на диске. Освободите место, повторите выгрузку вендорским скиллом `db-dump-xml`, перезапустите индексацию |
| `dump\Configuration.xml` обрывается на середине тега | То же: выгрузка не завершилась. `Configuration.xml` платформа пишет последним, поэтому обрыв виден именно в нём |
| После переполнения диска «побились» файлы | Проверьте размеры файлов проекта: часть могла стать пустой (так было с одним из конфигов — осталось 3 байта). Перекачайте вендорские файлы: `scripts\install-vendor-skills.ps1` |
| Индекс занимает много места | `.code-index\index.db` крупной конфигурации — несколько ГБ. Удалите `dump\.code-index` и пересоберите при необходимости |
| Скиллы не видны в Cline | Неверный каталог. Cline читает `~/.cline/skills` (глобально) и `<проект>/.cline/skills`. Каталог `~/.cline/data/skills` **не** читается |

## Полезные ссылки на логи

* `logs\dump-run.log` — выгрузка конфигурации
* `logs\install-mcp.log`, `logs\vendor2.log`, `logs\install-skills.log` — установка MCP, загрузка вендорских файлов, установка скиллов
* `mcp\code-index-mcp\daemon.log`, `serve.log` — индексация и выдача MCP
* `logs\watch-reindex.log`, `logs\reindex.log` — пересборка индекса
